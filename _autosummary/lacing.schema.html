lacing.schema#

Body schema registry, JSON Schema export, and migrations.

Every annotation’s body is validated against the schema named by its body_schema_uri (semver: annot://schema/<name>/v<major>). This module implements:

  • register_body_schema() — register a Pydantic v2 model for a schema URI.

  • validate() — validate an annotation’s body dict against its schema.

  • body_locations() — which body fields hold urls/paths (Location marker).

  • body_derived() — which body fields are derived from a sibling (Derived marker).

  • json_schema() — get the JSON Schema for a registered URI.

  • export_json_schemas() — write all JSON Schema artifacts to disk (under lacing/schema/<name>/v<N>.json by default), the upstream for json-schema-to-zod codegen.

  • register_migration() — register a forward migration from version N to N+1 of a body schema.

  • migrate() — upgrade a body dict (or whole annotation) through registered migrations.

See the lacing-schema-codegen skill and BACK-DOC §4.5.

Usage example:

from pydantic import BaseModel, Field
from lacing.schema import register_body_schema, register_migration

class WordBodyV1(BaseModel):
    model_config = {"frozen": True, "extra": "forbid"}
    text: str = Field(..., description="The word's surface form.")

register_body_schema("annot://schema/word/v1", WordBodyV1)

class WordBodyV2(BaseModel):
    model_config = {"frozen": True, "extra": "forbid"}
    text: str = Field(..., description="The word's surface form.")
    normalized: str | None = Field(None, description="Normalized form.")

register_body_schema("annot://schema/word/v2", WordBodyV2)

@register_migration(schema_name="word", from_version=1, to_version=2)
def v1_to_v2(body: dict) -> dict:
    return {**body, "normalized": None}

lacing.schema.export_json_schemas(target_dir, *, overwrite=True, include_meta=True, allow_empty=False)[source]#

Write every registered schema as JSON files under target_dir.

Layout: <target_dir>/<name>/v<N>.json. Returns the list of paths written, in registration order.

Parameters:

  • target_dir (str | Path) – Output directory. Created if missing.

  • overwrite (bool) – If False, refuse to write a file that already exists.

  • include_meta (bool) – If True, also write a <target_dir>/index.json mapping every URI to its file path and the Pydantic model’s qualified name (helps the codegen pipeline).

  • allow_empty (bool) – If True, permit an export from an empty registry. The default refuses, because the overwhelmingly likely cause is a missing import lacing.bodies and the write would destroy the committed artifacts.

Raises:

EmptySchemaRegistryError – Nothing is registered and allow_empty is False.

Return type:

list[Path]

lacing.schema.on_register(listener, *, replay=True)[source]#

Call listener(uri, model) whenever a body schema is registered.

For consumers that keep a process-wide view derived from the registry (e.g. one vocabulary of body_locations() over every schema) and so must hear about schemas registered after they first looked. With replay (default) the listener is first called for every schema already registered, so subscribing late loses nothing. Re-registering a URI notifies again. clear_registry() does not notify and keeps the listeners.

A listener that raises does not stop the others from being told; the first error is re-raised to the caller of register_body_schema() (the schema stays registered). Returns a zero-argument function that unsubscribes the listener (idempotent).

>>> seen = []
>>> off = on_register(lambda uri, model: seen.append(uri), replay=False)
>>> class _B(BaseModel):
...     pass
>>> _ = register_body_schema("annot://schema/doctest-on-register/v1", _B)
>>> seen
['annot://schema/doctest-on-register/v1']
>>> off()
>>> _ = _BODY_REGISTRY.pop("annot://schema/doctest-on-register/v1")  # test cleanup
Return type:

Callable[[], None]

lacing.schema.register_migration(*, schema_name, from_version, to_version)[source]#

Register a forward migration from v<from_version> to v<to_version>.

Decorated function takes a body dict and returns a new body dict. Migrations must be one major-version step at a time (to_version == from_version + 1).

Re-registering the same (schema_name, from_version) pair replaces the previous entry — convenient in tests, intentional for hot-reload.
